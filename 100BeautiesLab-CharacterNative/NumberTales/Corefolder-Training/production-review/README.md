## 規範のキャラ自身の絵とVRMを照合する

各行は同じキャラの公式コアフォルダ絵、原画に近い方位の実VRM、実VRMの三面図だよ。#16と#20は直立して比較できる公式2枚目を選んだ。最初の2列だけ外接枠を合わせ、右3列はすべて同じ世界縮尺にしている。原画に描かれた片目閉じ、首の傾きや尾のポーズも記録したうえで、中立姿勢の造形を見比べる。[公式絵と実VRMの6組](reference-pairs.png) ／ [番号・画像の出典と入力ハッシュ](reference-pairs.json)

| 規範 | 公式絵から実VRMに移したときの見え方 | 4体への適用 |
| --- | --- | --- |
| #4 モチ | 前髪の分け目と横の房は残り、丸い頭と目を受ける面が側面で分かる。肩衣装は固有の形。 | 中立の顔面と両眼の位置、目を閉じるメッシュの構成を共通基準にする。 |
| #16 ソロク | 帽子の下に大きな前房があり、側ポニーは中立時にも胴から離れて垂れる。瞼と淡い虹彩の境界で目が読める。 | ムイの前髪の量感と瞼、イズナのポニーと胴の重なりを比較する。 |
| #20 ハツカ | 白い髪・腹・尾が隣り合っても、側面では首の帯と丸い胴、後ろへ伸びる尾が別々の形として見える。 | 白い顎から白腹へのつなぎ、近い色の首まわりを側面でも読む。 |
| #22 フジ | 片目を閉じた絵に対して中立VRMは両目が開き、図柄を持つ虹彩が見える。連なった尾も初期姿勢では横へ伸びる。 | ムイの星形の瞳と、付属品や尾を動かしたときにも残すべき形の比較に使う。 |
| #25 フィズ | 絵の頬の短線はVRMでは淡い頬色になる。横の髪飾りは立体の房に重なり、背面の尾は薄い輪郭と色の切替で区別できる。 | ヨチカ・ハッコの頬、脇髪と装飾の接続を照合。ハッコの尾には #25 の輪郭幅0.5 mmを使用。 |
| #93 クミ | 正面絵の太い線の内側に見える毛先は、VRM背面では明るい毛先の色と丸い房の段差になる。横顔に太い黒線は出ない。 | イズナの尾に #93 の輪郭なしのMToon設定を使い、同系色の首・胴・房が光の中で分かれるかを確認。 |

対象4体の公式資料から参照するのは、主色、目の模様、髪型、耳の形、尾の房数と色分け、番号や装飾だよ。顔の構造、瞳の筆幅や頬の質感、毛束の立体化には上の規範を用いる。各モデルの原画とのシルエット比較は、ポーズや隠れ方の差を含む。数値を上げるために、規範の眼球位置や骨格を動かすことはしない。

## 頭と胴の素体に衣装を着せる

4体の胴には規範 #4 モチの実VRMから、肩衣装を取り除いた胴の1,078頂点を写したよ。顔面は #4 の中立形と表情を使い、顔を囲む34頂点を後頭部につないでいる。後頭部の形は #4・#25・#93 の実VRMの断面から復元した。頭頂は耳の付け根があるため、頭の中央を縦に切った輪郭と左右幅を使い、滑らかにつないだよ。[規範からの抽出](../extract_core_envelope.py) ／ [書き出し後の頂点・顔の継ぎ目・衣装の所属](core-envelope.json)

Unityでは `Face` と `Body` を表示すると共通の頭と胴、そこへ `Hair` と `Tail` を加えると各キャラの髪・耳・尾、さらに `Outfit` を加えるとムイの襟とブローチ、ヨチカの胸番号、イズナの腕章、ハッコの首飾りが見える。横顔や後頭部を含め、同じ位置にカメラを置いて確かめたよ。[Unityでの素体・髪と尾・着衣の比較](wardrobe.png) ／ [規範と共通素体を含む裸頭と胴](clay-cranial-base.png) ／ [修正前後の三方向](volume-revision.png)

尾は素体の巻いた1本を開き、194頂点・224面のメッシュが根元から先端に向かってどこで太り、細くなり、前へ曲がるかを確かめた。イズナとハッコはこの房の断面を曲がった中心線に沿わせている。二股の房には左右の先端をつなぐ面があり、根元から一続きの閉じた形として動く。尾の本数・毛色・分岐の位置はそれぞれの公式背面アトラスを参照したよ。[素体の断面と分岐の処理](../native_tail_profiles.py) ／ [各房への配置と配色](../atlas_tail_sculpt.py)

無彩色の比較は11体を同じ1.76 m幅・正投影で撮影した。全体・胴・尾に分けた各画像の左側が規範6体、右側の最上段が共通素体、その下が制作4体だよ。髪や尾の重なりはクレイ表示、輪郭線と毛色の見え方はUnityのMToon表示で確認できる。[全身のクレイ](clay-whole.png) ／ [胴のクレイ](clay-body.png) ／ [尾のクレイ](clay-tail.png) ／ [寸法・ハッシュ・撮影条件](clay-views.json)

## 頭を平面に投影して髪の交差を調べる

規範はそれぞれ本人の原画と正面・斜め・横・後ろの実VRMを並べた。制作4体には耳先から顎まで入る固定倍率のUnity画像を使い、同じ子の修正前後を比較している。頭部だけの輪郭図は、胴や尾に隠れる場所も共通の世界座標で正面・30度・90度から投影したものだよ。[規範6体と本人の原画](heads-reference.png) ／ [4体の原画と髪の修正前後](heads-revision.png) ／ [頭部だけの輪郭差](head-silhouettes.png)

面の交差は、別パーツの三角形が互いの面を横切る長さと、同じパーツの非隣接三角形が自分自身を横切る長さを測る。6方向から全身にレイを飛ばし、最初の衝突が交線から1 mm以内のものを画面に投影した。髪の根元など、他の面に隠れる部分を含む三次元の交線の総延長も別欄に保存してある。非常に小さな装飾や、ほぼ接するだけの面、テクスチャの透過はこの計測の対象外だよ。[修正前](head-contacts-before.json) ／ [修正後と規範](head-contacts.json) ／ [測定コード](check_head_contacts.py)

正面で見える交線の合計は、ムイが2,853→223 mm、ヨチカが1,800→487 mm、イズナが1,746→261 mm、ハッコが1,782→543 mm。最終値は4体とも規範6体の92〜634 mmに収まった。ヨチカとハッコには髪の房や頬との接点が残っているよ。

## 顔をどう比較したか

目の間隔は中立時の左右の眼球メッシュで測定したよ。頬幅は上唇の中心より18 mm高い位置で、正面の皮膚を横切る断面の幅。髪は含めない。目の間隔と頬幅は別々に検査して、側髪で隠れる頬の見え方はカラーの写真で確かめた。ワイヤー図には顔オブジェクトの実際の辺を表示し、まばたきで動く部分を青、「あ」で動く部分を橙で示しているよ。口内も透かしている。[顔メッシュと可動部](face-topology.png) ／ [測定と描画](compare_face_topology.py)

規範6体のHumanoidには顎の割り当てがなく、唇・口内の開閉は顔のシェイプキーで行うよ。4体の口縁・口腔壁・舌の192頂点を対応させ、素体で背骨にも追従していた口内を頭に追従させた。頭を12度回す試験と首を8度傾ける試験では、「あ」で動く各頂点が中立時の頭に対してずれた距離をUnityで測る。公式絵に見える頬から下顎の境界と、開閉する唇は個別に照合したよ。[規範6体の口の寸法](canonical-mouth.json) ／ [口の元メッシュと転送処理](../face_articulation.py)

左右それぞれのハイライトと瞳の模様には個別のUVを使い、眼球の位置・眼骨・瞼と頬の構造は実VRMから照合した。記録には元絵、規範の両眼、4体の中立・まばたき・視線移動と段階的な開口を収めているよ。[規範の目](reference-eyes.png) ／ [4体の目元](eye-detail.png) ／ [口と顎の比較](mouth-rig.png) ／ [VRM再読込後の顔と骨格](face-rig-reference.json)

## 撮影条件

Blender 5.3.0・VRM Add-on 4.10.5 で書き出したVRM 0.xを、Unity 6000.3.23f1・UniVRM 0.131.1 でインポートし、Play Modeで撮影する。共通の PC_RPAsset、リニア色空間、MToon10、正投影を使う。三面図は全10体が900 px角・正投影半高0.88 m。目の比較は半高0.30 m、口元は半高0.205 mだよ。原画を使う列は、各キャラの顔が分かる範囲で個別に切り出している。

髪と尾は120ステップ静置してから、1/60秒ずつ、最初の24ステップで胴を左右と前後に動かし、150ステップまで静置する。それぞれの毛先とウェイトを持つ実頂点が動く距離を記録する。表情はレンダラーごとにメッシュを新しくベイクして撮るよ。

4体をUnity本体のプロジェクトにもインポートして、編集用データから出力したVRMとバイト単位で照合した。Play Modeでは各13表情、ムイ8・ヨチカ11・イズナ10・ハッコ11本の揺れチェインを確認したよ。[規範6体と制作4体の三面図](three-views.png) ／ [髪・尾の動き](spring-motion.webp) ／ [首振り中の髪と瞳](spring-clearance.png) ／ [Play Modeの測定](play-mode.json)

首を12度回して口を65%開けた姿勢では、4体とも揺れる髪が瞳の前を横切る点は0だった。胴を左右に振る試験では、ヨチカの第18フレームで左目856サンプルのうち4点に頬毛が重なったよ。[10姿勢の髪と瞳の測定](spring-clearance.json) ／ [編集データとUnityに配置したVRMの照合](format-checks.json)

再検査には同じURP・UniVRM設定の検証用Unityプロジェクトで `CharacterReview.cs`、`CharacterReview.Gaze.cs`、`CharacterReview.SpringClearance.cs` をEditorアセンブリに配置し、参照に `VRM10`・`UniGLTF`・`UniGLTF.Utils`・`SpringBoneJobs` を追加する。プロジェクト直下の `character-review.json` に出力先と対象を指定し、Unityを `-batchmode -projectPath <検証用プロジェクト> -executeMethod CharacterReview.Start -logFile <ログ>` で起動する。撮影と変形検査が終わるとエディタが終了するよ。

```json
{
  "output": "D:/CorefolderReview",
  "models": [{
    "number": 85,
    "asset": "Assets/100BeautiesLab-CharacterVRM/NumberTales/Corefolder-85/Corefolder-85.vrm",
    "artwork": true,
    "check": true,
    "mouth": true
  }]
}
```

公式資料の元は `100BeautiesLab_CreationsDB/data/Works_NumberTales/` の `DataBases/db_Primary.json`、`Images/DB_Primary/corefolder/<番号>/`、`Images/DB_Primary/attr/tailsUnit/`。検査には公式絵・実際のメッシュ・実VRMのレンダーを使ったよ。今回の変更はメッシュ、UV、材質、リグと検査の改稿で、点群と画像モデルの追加学習は行っていない。
